BUILD
  1. Copy upstream src/ to a work directory, normalise it to LF, and apply the patch there:
     patch -p1 -d <dir> < source/d3d12multithreading-panplay.patch (the patch was made with "diff -ru orig src").
  2. Shaders (bit-identical on rebuild, 2026-10-26):
       vkd3d-compiler -x hlsl -b dxbc-tpf -p vs_5_0 -e VSMain -o shaders_VSMain.cso shaders.hlsl
       vkd3d-compiler -x hlsl -b dxbc-tpf -p ps_5_0 -e PSMain -o shaders_PSMain.cso shaders.hlsl
     The output is DXBC with ISGN, OSGN, RDEF, SHDR and STAT chunks. The only diagnostics are
     W5300 implicit-truncation warnings at shaders.hlsl:127-128; fxc warns there too.
  3. Exes: source/build-d3d12multithreading.sh <patched src> <DirectXMath/Inc> <out> x86_64 arm64ec
     The script compiles with clang++ -std=c++17 -O2 -DNDEBUG -DUNICODE and includes
     scripts/shim-mt/pix3.h (no-op PIX macros) and scripts/common/PanPlayHarness.h. It links with
     -static -s -mconsole -Wl,--no-insert-timestamp -ld3d12 -ldxgi -ldxguid -luser32 -lshell32 -lkernel32.
     The build ran under flock /home/flux/build-cache/build.lock. A second build from the final patch
     (2026-10-26, build/mt/out-check) produced bit-identical x86_64 and arm64ec exes.

MODIFICATIONS (all in source/d3d12multithreading-panplay.patch)
  - stdafx.h: drops D3Dcompiler.h and includes stdio.h and PanPlayHarness.h.
  - D3D12Multithreading.cpp:
    - Loads the precompiled shaders_VSMain.cso and shaders_PSMain.cso from the exe directory (ReadDataFromFile)
      instead of D3DCompileFromFile, so d3dcompiler_47.dll is not needed.
    - Present(1, 0) becomes Present(pph_sync_interval(), 0), followed by
      if (pph_on_present(hr)) PostQuitMessage(0).
    - DXGIDeclareAdapterRemovalSupport is resolved with GetProcAddress, because the mingw-w64 headers do not
      declare it.
    - swprintf_s becomes swprintf.
  - DXSampleHelper.h: sprintf_s becomes snprintf. A small RAII handle class replaces WRL Wrappers::FileHandle,
    which mingw-w64 does not have. NAME_D3D12_OBJECT uses L"" #x so clang accepts it.
  - Main.cpp: pph_init("d3d12-multithreading", argv, 1280x720). Exceptions are caught and printed as
    "DX12: FAIL ..." with exit code 1.
  - D3D12Multithreading.cpp (2026-10-29): OnDestroy now stops and joins the worker threads before closing their
    events. Upstream closes the begin-frame events while the workers wait on them, WaitForSingleObject then fails
    at once and the workers record into command lists that are already closed (vkd3d-proton: list->allocator is
    NULL after Close, SetDescriptorHeaps faults at d3d12core.dll+0x329F0, read of 0x70, after the PASS line).
  - DXSample.cpp: -warp and /warp must match exactly. Upstream compared only wcslen(arg) characters, so an
    empty argument or "-" also took the WARP path.
  The rendering code, scene, camera path, lights and threading are unchanged.
  PanPlayHarness.h times the run and the fps average from the first Present; startup is reported separately.
