# Mesa PanVK 26.3.0-devel (git-795ca7ff3e), build 122i

One universal `libvulkan_panfrost.so` for Mali GPUs on the `mali_kbase` kernel driver: Bifrost JM v6 and v7, Valhall JM v9 and CSF v10 to v14. Mali v15 (G2) is not fully supported. Minimum Android API 29, arm64.

driverInfo: `Mesa 26.3.0-devel (git-795ca7ff3e, p0175, 2026-10-31)`. Tag `panvk-kbase-v26.3.1`.

## Summary: what is new since RC4

RC4 (`panvk-kbase-v0.1.0-rc4`, 2026-10-17) was the last public driver. This release carries csf-v11 187-233, jm-v9 031 and jm-v7-wip 0006-0175 on top of it. In short:

- **Faster on every tested GPU.** On the POCO X6 Pro (Mali-G615, v11), DXVK D3D11 cube goes from 285 fps (RC4) to 683 fps; D3D11 feature-level tests from 668-705 fps to 1041-1294 fps. On the Lenovo TB336FU (Mali-G57, v9), the PanProbe suite takes about 55 % less time than RC4 (see the note on the RC4 total), and GS strips with restart go from 1935 us to 17 us per draw (about 110x).
- **D3D12 (vkd3d-proton) works.** On RC4 every D3D12 test failed on the two local devices. It now runs, with no DEVICE_LOST in the tested runs.
- **Less driver memory.** The game process holds about 160 MB less GL/driver memory than on RC4 (build 116 and later). On v11 the cold compile of the BC transcoders dropped from 5.0 s (116) to 0.54 s (RC4 0.46 s).
- **More hardware.** Bifrost v6 and v7 get geometry shaders, transform feedback, tessellation and the DXVK feature set (jm-v7-wip). The Mali G1-Ultra (v14) runs the PanProbe suite 41/41.
- **Tiler out-of-memory is handled** (incremental rendering) on v11, v12 and v13, instead of a lost device.
- **MangoHud GPU load and VRAM** are available on Android (driver side).

Three builds are compared below. **RC4** is the last public driver. **116** is an internal build (jm-v7-wip through 0151) that was never published. **26.3.1** is this release (build 122i, 0006-0175). "–" means no data was measured; nothing in the tables is estimated.

## What was optimised

Patch ids are from `patches/csf-v11`, `patches/jm-v9` and `patches/jm-v7-wip` (four-digit ids are jm-v7-wip). Every line below is taken from the patch headers.

### GPU-emulated paths (GS, XFB, tessellation, BC, robustness)

| patch | what it does |
|---|---|
| 0150 | v9 JM compute jobs set "allow merging workgroups" (libpan tess kernels, small dispatches) |
| 0151 | gpu_prerast kernels (GS, XFB, polygon fill mode, vertex stores, TES as VS) merge workgroups |
| 0152 | v9: merged vertex shaders fetch instance-rate attributes with vertex frequency (fixes a wrong-attribute bug of 0151; `large_draw` 10.2 s to 7.2 s on the G57) |

## Known issues

- **POCO X6 Pro (v11), D3D11 and D3D10 cubes:** the 1 % low fps is lower than RC4 and 116 (about 47 vs 103 on RC4 and 52-56 on 116) while the average is far higher. The 1 % low of D3D11 FL 10_0 is also lower (82 vs 123 on RC4 and 111 on 116); FL 10_1 to 11_1 are higher (172 to 203).
- **Fallout 4 on DXVK:** the face is drawn black. This is a known bug, not fixed in this release.
- **D3D12 feature level 12_x is not supported.** The FL 12_0 to 12_2 tests report UNSUPPORTED and run at the 11_1 fallback. vkd3d-proton D3D12 up to FL 11_1 runs, but D3D12 is not a focus of this release.
- **Firebase single-run drops are unconfirmed:** Galaxy A31 (v7) cube -20 % and D3D9 -26 %, Pixel 7 (v10) cube -11 % against 116, one run each. Test Lab quota did not allow a repeat.
- **TB336FU PSS is above RC4** on PanPlay scenes s7, s8 and s9 (s8 +25, s7 +48, s9 +65 MB). 116 had the same memory, so this predates 26.3.1.
- **Cold shader cache:** the first `bc_decode` after a cache wipe is 0.54 s on the X6 Pro (RC4 0.46 s); `bc_level` on v9 is 107 ms in the cold test (RC4 108).
- **v12, v13, v14 runs are single runs** (Samsung remote lab sessions); small differences (±10 %) are noise. v12 and v13 were run on 122h, not 122i.
- **v15 (Mali-G2)** is not fully supported.
- **Mali-G720 MC8** `gs_viewport_depth` failed now and then on an older beta for one user; untested since.

## Install and update

Mali GPU on the `mali_kbase` kernel driver, Android 10 or newer (API 29), arm64. 

| you use | file |
|---|---|
| PanPlay or PanProbe | nothing to install, the driver is bundled ([PanPlay 1.3.1](https://github.com/zenithblue-oss/panplay/releases/tag/panplay-v1.3.1), [PanProbe 1.3.2](https://github.com/zenithblue-oss/panprobe/releases/tag/panprobe-v1.3.2)) |
| GameNative and other adpkg launchers | `PanVK-Kbase-Android-...adpkg.zip`, or `libvulkan_panfrost-android-aarch64.so` with `panfrost_icd.aarch64.json` |
| Winlator | `...-winlator.zip` |
| Winlator cmod | `...-cmod.zip` |
| Bannerlator | `...-bannerlator.zip` |
| Ludashi | `...-ludashi.zip` |
| GameHub | `...-gamehub.zip` (the library is named `libvulkan_freedreno.so` inside) |
| adrenotools-based launchers | `...-adrenotools.zip` |
| emulators (glibc) | `...-EMULATOR.zip`, or `libvulkan_panfrost-glibc-aarch64.so` |

Import the zip in the launcher's driver manager and select it. To update from RC4 or an earlier build, import the new zip and select it again; the old one can stay installed for A/B. All launcher zips carry the same Android `.so`; they only differ in packaging. Check downloads against `SHA256SUMS`. Please send PanProbe results and PanPlay session logs when you test a GPU not in the table.
