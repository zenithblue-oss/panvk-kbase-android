### Verdict — Round 1 blockers are partially resolved
The revised plan adequately addresses the global FL override and the 16 GiB eager allocation. It preserves vkd3d’s derived tiled-resource tier of 0 and gives JM/v14 eager backing a bounded lifetime and budget. “Tier 1-minus-Aliased” is useful as design shorthand only. The hardware gate is worth running, but its current pass criteria can accept a driver that returns stale data after unbind.

### Remaining risks and nuances

1. **A completed CSF unbind can expose the previous owner’s data.** Unbind clears the software residency bit and signals the bind fence. The worker then wakes and uncommits the page. A consumer waiting on that same fence can read the old physical page first. A generation counter cannot close this interval. Require a test that writes a distinctive pattern, unbinds, delays the worker, and samples immediately from a second queue. The first legal sample must already see the zero-backed result. Fixed-function writes have a related problem: a post-pass clear comes too late if an input attachment or resolve can observe the write within the pass.
2. **T10d can pass after explicitly observing a nonzero recommitted page.** The probe sets `tile_cycle = 1` from commit counts alone. A failed CPU mapping also leaves zeroing unverified. With the one-page fallback, the marker checks the last page, while the first page stays backed and can retain its contents. Make zeroing a separate required result for the no-clear path, including the retained page, and repeat the check through GPU reads.
3. **Shadow copies need a memory-visibility contract.** A synchronized host write to host-visible `VkDeviceMemory` after bind changes the source allocation while the GPU reads its shadow. Conversely, a GPU write followed by a synchronized host read can expose stale source data until unbind. Neither case requires sparse aliasing. Restrict sparse memory type eligibility to types the design can keep coherent, or demonstrate both directions while the tile stays bound. Dirty-bit copy elision also needs a conservative rule for device-address and bindless writes whose destinations cannot be enumerated at submit.
4. **The 256 MiB cap has an enforcement point on eager allocations, but none is specified for GPU-fault growth.** Sampling previously untouched unbound tiles can commit physical pages without a bind call or corresponding worker entry. Specify how worst-case growth is charged before access, or identify a kernel-enforced limit and demonstrate recovery at that limit. Include a read sweep with no intervening binds. An eager fallback should pass its own hardware gate on each enabled backend.
5. **The census needs to exercise the path the override unlocks.** A game that exits at the FL check produces an empty trace. Run a diagnostic forced-FL profile through representative gameplay and asset streaming, recording reserved-resource creation, tile mappings and `CopyTiles`. Treat the result as evidence for that title build and configuration. Also distinguish title-specific SM 6.2 requirements from the FL 12_0 requirement; Microsoft lists SM 6.0 for that level.

### Final recommendation
Approve the title census and S0 hardware experiments. Hold S1–S4 and Vulkan sparse capability exposure until the plan defines when unbind becomes visible, how bound memory stays coherent, and how autonomous growth stays within budget. A per-title override can proceed independently once the forced-FL run supports it.
