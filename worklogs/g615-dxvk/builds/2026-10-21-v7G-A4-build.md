## xfb vs_clip_cull_capture (mismatch=4)

- Test (`tests/dxvk/vulkan/xfb/xfb.vert` MODE 6): 4 points, record stride 8 =
  {gl_ClipDistance[0] = 0.25*i - 0.5, gl_CullDistance[0] = -1.5 + i}. Mismatch=4 in A1, A2 and
  A3, so 0032 (jm-v7 023) changed nothing visible.
- The wrong component is cull, all 4 vertices. The xfb info is right (vk_spirv_to_nir() merges
  clip+cull before gathering it, cull = CLIP_DIST0.y) and 0032 maps it to CULL_DIST0.x
  correctly. But on v6/v7 the HW VS variant runs `panvk_lower_cull_dist_flags_intr()`, which turns
  every CULL_DIST0/1 store into the FS kill flag `cull < 0 ? 1.0 : 0.0` (the v7 FS kill reads
  CULL_DIST0, `PANVK_FS_CULL_KILL_SLOT0`). The passthrough copied the flags:
  captured 1,1,0,0 vs wanted -1.5,-0.5,0.5,1.5, i.e. 4 mismatches. Clip was right.
  (Before 0032 it read CLIP_DIST0.y = the 1.0 pad, also 4 mismatches.)
- Fix 0025 (jm-v7 026): a VS/TES whose xfb captures a cull component also writes the raw
  distances to TEX0/1 (`PANVK_XFB_RAW_CULL_SLOT0/1`: never used by Vulkan, generic to pan, and the
  v7 GS emulation does not pass slots below VAR0 to the FS). `panvk_vs_store_xfb()` maps cull
  components there. The FS kill flags stay in CULL_DIST0/1.

## large_draw tess_* (written capped at 16384/8192, generated=-1)

- `generated=-1` is on every case, passing ones too: `primGenQuery=0`
  (primitivesGeneratedQuery not exposed), so the test prints -1. Not the failure.
- The cap is in the log: `panvk: tessellated draw of 70000 patches, only 8192 are drawn`.
  `PANVK_TESS_MAX_PATCHES` was 8192, the size the serial `panlib_v7_tess_prefix()`
  (KERNEL(1)) was written for. The setup keeps whole instances up to max_patches:
  - tess_direct/indirect: 70000 isoline patches, point mode, 2 points each -> 8192*2 = 16384.
  - tess_tri_direct/indirect: 70000 triangle patches -> 8192 triangles.
  - tess_instanced: 1 patch x 9000 instances -> 8192 instances * 2 = 16384 (bad=2 = counter and
    query checks, not an instance-offset bug).
  Not the GS output budget (`PANVK_TESS_GS_MAX_PRIMS` = 2M) and not the 4M-vertex cap of 0032.
- Fix 0026 (jm-v7 027): `panlib_v7_tess_prefix()` is one workgroup of 256 (run sums, workgroup
  scan, each run writes its prefix and finds its first patch past the budget, saturating sums);
  `PANVK_TESS_MAX_PATCHES` = 1 << 18, still bounded by the 160 MB tess arena per TCS output size.
  A direct draw sizes the tessellator grid for its own patches (not 4096 workgroups).
