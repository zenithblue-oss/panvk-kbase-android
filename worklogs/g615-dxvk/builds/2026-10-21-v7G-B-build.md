## Root causes

### B. Primitive restart in the geometry emulation
The v7 GS emulation (jm-v7 007) assembles strip/fan input primitives by position in the
index stream (`gs_input_record()`), with no notion of restart. A restart index made
primitives straddle the cut (extra red in polygon-mode LINE, which goes through the 0017
passthrough GS), fans kept the draw's first vertex as centre, strip parity was wrong after
a cut, and the primitives containing the restart vertex read garbage records (black). Fix
(0030): for an indexed strip/fan/strip-adjacency draw with restart, a serial libpan kernel
(`panlib_v7_gs_restart_list`) cuts the index stream into restart-free runs and writes the
run primitives as a 32-bit list plus a new VkDrawIndexedIndirectCommand; the emulation then
assembles a plain list. gl_PrimitiveIDIn counts assembled primitives (no reset at a cut).

### D1. gs_viewport_depth
The tiler has one VIEWPORT descriptor; 0016 programmed the union of the viewports' depth
ranges, so per-viewport depth clamp and clip were wrong (0.375 instead of clamped 0.25,
etc.). The csf-v11/193 overwrite (coordinator note) does not exist on v7: its scissor
planes are written by the emulation itself in CLIP_DIST1 and nothing rewrites them. Fix
(0030 too, see README): when the selectable viewports' depth ranges differ, each viewport
gets its own copy of the emulation's index list (only its primitives) and its own tiler job
with its own VIEWPORT (scissor box and depth range). Limit: primitives of different
viewports with overlapping scissor boxes are no longer rasterized in API order.

### D2. vs_viewport_index
Bifrost has no hardware viewport-index varying (CreateGraphicsPipelines -13). A last
pre-raster VS/TES writing gl_ViewportIndex is now compiled for clip space and drawn through
the passthrough GS, the index carried in the generic slot `PANVK_GS_VIEWPORT_INDEX_SLOT`
and turned back into gl_ViewportIndex in the passthrough. shaderOutputViewportIndex is
exposed on v6/v7.

### C. Tessellation caps
px=682 = floor(2^20 / 1536): PANVK_TESS_MAX_INDICES (1M) with level-16 quads (1536
indices per patch). px=16 = 8192 * 3 / 1536: PANVK_TESS_GS_MAX_PRIMS (8192) for TES->GS.
Fix: 8M indices (arena 160 MB growable), 2M primitives into a GS after the TES, the GS
emulation buffers of a tess eval draw from a growable GPU-only pool, and a 4M-vertex
indirect varying buffer (growable). shaderTessellationAndGeometryPointSize: TES point mode
uses the TES gl_PointSize, GS point output writes an FP32 point size array, GS/TCS read
gl_in[].gl_PointSize from the VS fp16 buffer, the point passthrough forwards it.
