## 1. VMR secondaries (PROGRESS item 12)

The note ("update `fb.nr_samples` / `evaluate_per_sample`") comes from the beta.14/15 G57 run (`cnt[slot 1 sample 1] = 0, want 256`) and the root cause in `docs/universal/v9-jm/README.md:139`. jm-v9/018 already does both things:
- `v9_attachmentless_samples()` runs at the start of `v9_cmd_draw`. If the pass has no attachments and the sample count changes, it closes the batch (only when its FBD exists), sets `fb.nr_samples` and resets `fb.layout.sample_count`.
- The v9 DCD sets `flags_0.evaluate_per_sample` and `multisample_enable`.
- `variableMultisampleRate = PAN_ARCH >= 9`.

On JM, secondaries are `vk_cmd_enqueue` command lists. They replay through the primary's `CmdDraw`, so they take the same path. Resume in the same command buffer keeps the batch and `nr_samples`. Resume in a new command buffer re-inits the render state, and the first draw sets the count again. beta.17 only skipped the test (`vmr=0`), and 018 was not in it. Phase 5 on the G57 did not list `vmr_secondary` as a failure. No new code. Device check: PanProbe `vmr_secondary` on a v9 device must run all 13 cases (not SKIP) and pass.

## 4. X11 surface re-creation OOHM (PROGRESS item 7, row E): csf-v11/198

Root cause: `wsi_CreateXlibSurfaceKHR` and `wsi_CreateXcbSurfaceKHR` call `get_visualtype_for_window()` (query_tree + get_window_attributes). They return `VK_ERROR_OUT_OF_HOST_MEMORY` when it gives NULL, and it gives NULL whenever the window is gone. That is exactly the case after DXVK's OUT_OF_DATE -> SURFACE_LOST -> re-create sequence. vkCreate*SurfaceKHR cannot return SURFACE_LOST, so the patch creates the surface anyway (opaque, `has_alpha = false`). `x11_surface_get_capabilities` then returns `VK_ERROR_SURFACE_LOST_KHR` from the failed `xcb_get_geometry`. It also frees the xcb error on that path, which used to leak. OOHM is now returned only for a real allocation failure or a libxcb dlopen failure.

## 5. Negative-origin damage rects (117 review, item 22): csf-v11/199

Root cause: `x11_queue_present` stored the VkPresentRegionKHR rects without clipping. The 117 MIT-SHM path skipped any rect with x < 0 or y < 0, so the visible part was never copied (stale pixels). The PutImage SW path used them unclipped and read before the image. The patch clips each rect to the swapchain extent with 64-bit math and drops empty rects. If none remain, the whole image is presented, as with no damage. The XFixes region gets the clipped set. The SHM loop keeps its bounds check as a safety net.
